# AI 集成重构：手写客户端 → Spring AI + DashScope Provider

> 状态：**计划文档**（已执行, 当前校验完成）
> 需求来源：将手写 AI 处理转换为 Spring AI，大部分逻辑顺应 spring-ai；在 deepseek/mock 基础上增加 dashscope（阿里云百炼），代码抽象化便于扩展 provider，配置同步修改。

---

## 1. 背景

当前 AI 层为手写实现，位于 `ai-ticket-server/src/main/java/com/aics/ticket/ai/`：

| 文件 | 职责 |
|---|---|
| `AiChatClient.java` | 接口：`complete(String)`、`stream(String)`、`embed(String): List<Double>`、`embedBatch(...)` |
| `DeepSeekAiChatClient.java` | RestTemplate 手写直连 OpenAI 风格 `/chat/completions`、`/embeddings`；含 SSE 流式 `streamChat(message, Consumer<String> onToken, Runnable onComplete)` |
| `MockAiChatClient.java` | 兜底 mock：模板回复 + 哈希伪向量（64 维） |
| `config/AiConfig.java` | `@Bean @Primary AiChatClient`，按 `app.ai.provider`（deepseek/mock）选择 |

消费方：
- `chat/ChatService.java` — `send()` 用 `complete()`；`sendStream()` 里 `instanceof DeepSeekAiChatClient` 走真流式，否则 `stream()` 模拟流式
- `chat/ChatController.java` — 注入 AiChatClient 字段但未直接使用（SseEmitter + 线程池 + 回调）
- `kb/FaqService.java` — `semanticMatch()` 用 `embed(message)` 生成查询向量，与 `faq_entry.question_vector`（JSON 字符串列）暴力余弦比对；`rebuildVectors()` 只补空；`generateVector()` 用 `embed(entry.question)`
- `common/VectorUtils.java` — `cosineSimilarity(List<Double>, List<Double>)`、`toJson`、`fromJson`

目标：迁移到 **Spring AI 1.0.0**，以 `ChatModel` / `EmbeddingModel` 接口作为统一抽象，Mock 退化为兜底，新增 dashscope provider。

## 3. DashScope 接入方案

**选定方案 A（推荐）**：依赖 `spring-ai-alibaba-core`（只含模型类，**无自动配置**），手动构造 bean。

- 类路径（已核实 `spring-ai-alibaba-core:1.0.0.2`）：
  - `com.alibaba.cloud.ai.dashscope.api.DashScopeApi`
  - `com.alibaba.cloud.ai.dashscope.chat.DashScopeChatModel`
  - `com.alibaba.cloud.ai.dashscope.embedding.DashScopeEmbeddingModel`
- 构造方式（已核实）：
  - `DashScopeApi.builder().apiKey(String).baseUrl(String).build()`
  - `DashScopeChatModel.builder().dashScopeApi(api).defaultOptions(DashScopeChatOptions.builder().withModel(...).build()).build()`
  - `new DashScopeEmbeddingModel(api)`（默认模型 `text-embedding-v2`）
- **必须常驻依赖、不能用 profile**：`AiConfig` 直接引用 DashScope 类，若放 `ai-alibaba` profile（非默认激活），默认 `mvn compile` 会编译失败。

**备选方案 B**：`spring-ai-alibaba-starter-dashscope` + 在 application.yml 排除 7 个自动配置类：

```yaml
spring:
  autoconfigure:
    exclude:
      - com.alibaba.cloud.ai.autoconfigure.dashscope.DashScopeChatAutoConfiguration
      - com.alibaba.cloud.ai.autoconfigure.dashscope.DashScopeEmbeddingAutoConfiguration
      - com.alibaba.cloud.ai.autoconfigure.dashscope.DashScopeAgentAutoConfiguration
      - com.alibaba.cloud.ai.autoconfigure.dashscope.DashScopeImageAutoConfiguration
      - com.alibaba.cloud.ai.autoconfigure.dashscope.DashScopeAudioSpeechAutoConfiguration
      - com.alibaba.cloud.ai.autoconfigure.dashscope.DashScopeAudioTranscriptionAutoConfiguration
      - com.alibaba.cloud.ai.autoconfigure.dashscope.DashScopeRerankAutoConfiguration
```

> 为什么必须排除：`DashScopeChatAutoConfiguration` 类级只有 `@ConditionalOnClass(DashScopeApi.class)`（无 property 门槛），api-key 为空时内部 `Assert.hasText` **直接抛异常启动失败**——mock 模式（不配 key）会崩。

## 6. AiConfig — provider 工厂（对话/向量解耦）

```java
@Value("${app.ai.provider:mock}")          private String provider;
@Value("${app.ai.embedding-provider:mock}") private String embeddingProvider;
@Value("${app.ai.deepseek.api-key:}")      private String dsApiKey;
@Value("${app.ai.deepseek.base-url:https://api.deepseek.com}") private String dsBaseUrl;
@Value("${app.ai.deepseek.completions-path:/v1/chat/completions}") private String dsPath;
@Value("${app.ai.deepseek.chat-model:deepseek-chat}") private String dsModel;
@Value("${app.ai.dashscope.api-key:}")     private String dscApiKey;
@Value("${app.ai.dashscope.base-url:https://dashscope.aliyuncs.com}") private String dscBaseUrl;
@Value("${app.ai.dashscope.chat-model:qwen-plus}") private String dscChatModel;

@Bean @Primary
public ChatModel chatModel() {
    if ("deepseek".equalsIgnoreCase(provider) && StringUtils.hasText(dsApiKey)) {
        return OpenAiChatModel.builder()
            .openAiApi(OpenAiApi.builder()
                .apiKey(dsApiKey).baseUrl(dsBaseUrl).completionsPath(dsPath).build())
            .defaultOptions(OpenAiChatOptions.builder().model(dsModel).build())
            .build();
    }
    if ("dashscope".equalsIgnoreCase(provider) && StringUtils.hasText(dscApiKey)) {
        return DashScopeChatModel.builder()
            .dashScopeApi(DashScopeApi.builder().apiKey(dscApiKey).baseUrl(dscBaseUrl).build())
            .defaultOptions(DashScopeChatOptions.builder().withModel(dscChatModel).build())
            .build();
    }
    return new MockChatModel();   // key 缺失 / mock：兜底，保证无 key 也能启动
}

@Bean @Primary
public EmbeddingModel embeddingModel() {
    if ("dashscope".equalsIgnoreCase(embeddingProvider) && StringUtils.hasText(dscApiKey)) {
        return new DashScopeEmbeddingModel(
            DashScopeApi.builder().apiKey(dscApiKey).baseUrl(dscBaseUrl).build());
    }
    return new MockEmbeddingModel();
}
```

**要点**：
- 对话与向量 provider 完全解耦。DeepSeek 无 embedding API，推荐 `provider=deepseek` + `embedding-provider=dashscope`。
- 扩展新 provider = 加一个依赖 + 一个分支 + 一段配置，即为抽象化目标。

## 7. ChatService 流式改法

方法签名**不变**：`sendStream(String message, Long conversationId, Long userId, Consumer<String> onToken, BiConsumer<Long, String> onComplete)`。FAQ 命中分支（切句模拟流式）原样保留。

未命中分支替换（删除 `instanceof DeepSeekAiChatClient` 硬编码）：
```java
Prompt prompt = new Prompt(List.of(
    new SystemMessage(systemPrompt),   // 抽到配置 app.ai.system-prompt
    new UserMessage(message)));

StringBuilder fullAnswer = new StringBuilder();
chatModel.stream(prompt).subscribe(
    resp -> {   // onNext（reactor 线程）
        String text = resp != null && resp.getResult() != null && resp.getResult().getOutput() != null
            ? resp.getResult().getOutput().getText() : "";
        if (text != null && !text.isEmpty()) {
            fullAnswer.append(text);
            onToken.accept(text);      // 回调契约与现 SseEmitter 一致
        }
    },
    err -> {    // onError：沿用原 streamChat 兜底语义
        onToken.accept("[AI 服务异常: " + err.getMessage() + "]");
        saveMessage(conversation.id, "AI", null, fullAnswer.toString());
        conversationMapper.updateById(conversation);
        onComplete.accept(conversation.id, fullAnswer.toString());
    },
    () -> {     // onComplete：Flux 正常结束
        saveMessage(conversation.id, "AI", null, fullAnswer.toString());
        conversationMapper.updateById(conversation);
        onComplete.accept(conversation.id, fullAnswer.toString());
    });
```

`send()`（非流式）：
```java
ChatResponse resp = chatModel.call(new Prompt(new UserMessage(request.getMessage())));
answer = resp.getResult().getOutput().getText();
```

> 说明：`sendStream` 本就在异步线程运行、无 `@Transactional`，Flux 完成在 reactor 线程执行 DB 写入——每条 SQL 自成一事务，与现状一致。

## 8. FaqService 向量适配

- `semanticMatch`：`float[] query = embeddingModel.embed(message)`；遍历时保留 `stored != null && stored.size() == query.length` 维度守卫，`score = VectorUtils.cosineSimilarity(query, VectorUtils.toFloatArray(stored))`。
- `generateVector`：`float[] vec = embeddingModel.embed(entry.question); entry.questionVector = VectorUtils.toJson(VectorUtils.toList(vec));` —— `question_vector` 仍存 JSON 数字串，**DB 无迁移**。
- `rebuildVectors()`（签名不变，`/admin/faq/vectors/rebuild` 接口不动）——改为自动处理维度变化：
```java
public int rebuildVectors() {
    List<FaqEntry> entries = entryMapper.selectList(new QueryWrapper<FaqEntry>().eq("enabled", 1));
    if (entries.isEmpty()) return 0;
    int targetDim = embeddingModel.embed(entries.get(0).question).length;   // 探针当前维度
    int count = 0;
    for (FaqEntry entry : entries) {
        List<Double> stored = VectorUtils.fromJson(entry.questionVector);
        if (stored == null || stored.size() != targetDim) {   // 覆盖空向量 + 旧维度
            generateVector(entry);
            entryMapper.updateById(entry);
            count++;
        }
    }
    return count;
}
```
切换 embedding provider（mock 64 维 → dashscope 1536 维）后，旧维度向量在 `semanticMatch` 被维度守卫跳过，直到 `rebuildVectors()` 重建——无需人工干预。

## 10. 两个关键"坑"（实现时必须处理）

1. **DeepSeek base-url 语义变化**：`OpenAiApi` 最终 URL = `baseUrl + completionsPath`。原 yml 的 `base-url: https://api.deepseek.com/v1` 若配默认 path 会拼成 `.../v1/v1/chat/completions`。迁移后 `base-url` 只写 host，path 单独配 `/v1/chat/completions`。
2. **DashScope 自动配置缺 key 启动失败**：见第 3 节——用 core 模块（无自动配置）规避，或 starter + `spring.autoconfigure.exclude`。

## 11. 实现时需验证的 API 细节

1. `ChatOptions.builder()` 是否存在（`spring-ai-model` 1.0.0）：用于 `MockChatModel.getDefaultOptions()`；若不存在返回 `null`（我们只调 `call`/`stream`）。
2. `EmbeddingModel.embed(List<String>)` 在 1.0.0 返回 `List<float[]>`（**非** `List<Embedding>`）；Mock 实现走 `call(EmbeddingRequest)` 返回 `EmbeddingResponse`。
3. `DashScopeChatOptions.builder().withModel(...)` 方法名（源码已确认；编译报错再核对）。
4. `OpenAiChatModel` 最小 builder 内置 `DEFAULT_TOOL_CALLING_MANAGER` 与默认 retry，无需显式提供 `ObservationRegistry`/`RetryTemplate`。
5. mybatis-plus 3.5.9 + Boot 3.4.5 的 `@MapperScan("com.aics.ticket.**.mapper")` 冒烟确认。
6. springdoc 若 2.7.0 仍有告警可升 2.8.x。

## 12. 验证方案

1. `mvn -q compile`（默认 dev）：Boot 3.4.5 + spring-ai 1.0.0 + dashscope core 三组依赖解析无冲突、无编译错。
2. **mock 冒烟**（无任何 key）：`mvn spring-boot:run` → `/api/chat/messages` 返回 mock 回复、`/api/chat/messages/stream` SSE 逐 token、`/api/admin/faq/vectors/rebuild` 返回 64 维向量。**专门验证"无 key 不崩"**。
3. **dashscope 冒烟**（配 `DASHSCOPE_API_KEY`）：`provider=dashscope, embedding-provider=dashscope` → 对话 + rebuildVectors 生成 1536 维、语义匹配生效。
4. **deepseek 冒烟**（配 `DEEPSEEK_API_KEY`，`embedding-provider=dashscope`）：确认 URL 拼成 `https://api.deepseek.com/v1/chat/completions`（无 `/v1/v1`）、流式逐 token 正常。
5. **回归**：FAQ CRUD、转人工（`transferHuman`）、Swagger `/v3/api-docs`（验证 springdoc 2.7.0）。
